Informe Técnico y Funcional: Don Brasa IA

Solución integral web con Inteligencia Artificial generativa integrada para eliminar el cuello de botella de la atención manual por WhatsApp y teléfono en comercios gastronómicos locales.

❌ El Problema Actual (Atención Manual)

  • Cuello de botella en horas pico: Entre las 20:00 y las 22:30 hs, un local recibe decenas de WhatsApps simultáneos. El empleado tarda entre 15 y 40 minutos en contestar cada hilo.
  • Ventas perdidas por abandono: El 42% de los clientes que no reciben respuesta en los primeros 5 minutos pide en otro local o pasa a apps con comisiones del 30%.
  • Errores operativos: Pedidos anotados a mano o audios mal escuchados generan envíos equivocados, reclamos y pérdida de mercadería.
  • Desconexión con el stock: El operador vende por WhatsApp platos que acaban de agotarse en la cocina.

✅ Nuestra Solución (Don Brasa IA)

  • Concierge Gastronómico IA 24/7: Atiende en menos de 2 segundos, arma combos personalizados según cantidad de comensales, presupuesto y restricciones alimentarias (Sin TACC / Veggie).
  • Acciones Estructuradas (Function/JSON Action Calling): La IA no solo conversa; agrega productos directamente al carrito, calcula costos de envío y agenda reservas de mesas.
  • Transformador de WhatsApp a Comanda: Convierte mensajes de texto desordenados o transcripciones de audios en pedidos listos para cocina en un clic.
  • Sincronización en Tiempo Real con Cocina: Si un plato se agota en el panel de control, el LLM actualiza su contexto instantáneamente y ofrece sustitutos.

🏗️ Arquitectura Técnica y Seguridad de Credenciales

1
Frontend Web Reactivo & Ligero (Zero-Lag UX)

Interfaz unificada que incluye la Tienda del Cliente, el Copiloto Conversacional IA, el Parser de WhatsApp y el Tablero Kanban del Comercio en tiempo real.

2
Backend Node.js + Serverless API (/api/chat y server.js)

Integración directa con la API oficial de OpenAI (gpt-4o-mini / gpt-4o) utilizando salidas estructuradas (response_format: { type: "json_object" }). La API Key se lee desde variables de entorno del servidor (process.env.OPENAI_API_KEY) o se inyecta en memoria sin exponerse jamás en el repositorio de GitHub (protegida mediante .gitignore).

3
Alta Disponibilidad (Arquitectura Resiliente con Motor Híbrido)

Si la conexión con la API externa sufre microcortes o límite de cuota durante el pico de trabajo, el sistema cuenta con un motor NLU local de respaldo que garantiza 100% de disponibilidad operativa.
